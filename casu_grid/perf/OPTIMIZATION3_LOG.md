# Optimization III — experiment ledger

* Start: **2026-10-13 23:39 EDT** (epoch 1791949175); deadline 2026-10-14 07:39 EDT. Branch `optimization3` (worktree `Reinforcement-Unknown-Isaac-opt3`), starting commit `0d46520`.
* Machine: i7-11700K (8C/16T), RTX 3070 8 GB, 32 GB, Fedora 44; Isaac Sim 4.5.0 / Isaac Lab 2.1.1, PhysX on CPU, 2 PhysX threads per worker (min 2).
* Experiment: XY1 mini-world (128 × 128, independent terrain, compound collider, 16 × 64 × 64 spatial observation, 7 action heads, 10 ticks/decision, PPO rollout 64 / minibatch 32 / 2 epochs, 16,385 parameters).
* Throughput accounting (all benchmarks): `end-to-end = decisions / (collection_seconds + optimization_seconds)` over steady updates (first update dropped), taken from the trainer's own per-update timers;
  rollout = decisions / collection_seconds. Benchmark: `perf/../isaac_training_benchmark.py --terrain-mode independent --config workbench/experiments/xy1_point_navigation_mini.py`, runner `bench.sh` (scratch).
  `random-policy` regime: PPO has not learned; the near-uniform policy digs and crouches constantly, i.e. the worst case for the simulator.

> **Note.** Figures in the entries below were measured over the whole campaign, partly while a stale diagnostic process occupied one logical core (01:57–05:55). The final, clean-machine baselines and speed-ups are in `OPTIMIZATION3_REPORT.md` (section B).

## Profile (A) — where the time went (16 × 4)
* Trainer process (cProfile, 3 updates, 15.2 s): waiting for workers 5.6 s; `run_backward` 3.7 s; `conv2d` forward 2.75 s; `relu` 0.7 s — **the CPU runs the 16 × 64 × 64 convolution network for inference and PPO** (`train.py` hardcoded `device='cpu'`; the RTX 3070 was idle).
* Workers (averaged per 64-decision update): pre-phase 0.13 s, tensor write 0.12, PhysX 0.33, tensor read 0.06, controller-post + crouch-shape switching 0.50, observation construction ≈ 0.25, straggler wait 0.45 (24 % of the env step), IPC 0.085.
* Single-process 4-world cProfile: PhysX 27 %, crouch-shape switching (`set_level`) 27 %, reference Python controller ≈ 35 %, XY1 observation encoder 6 %. The mini-world does **not** use the compiled controller (`_build_fast_runtime` returns `None` for it).

### Rejected or neutral experiments (kept for the record)
| hypothesis | result | decision |
|---|---|---|
| more PhysX threads per worker | 8 × 3 threads 1734, 8 × 4 1693 vs 8 × 2 1725 decisions/s; 1 thread hangs PhysX in worker processes (known, `worker_physx_threads >= 2`) | keep 2 |
| more workers than physical cores | 64 × 10: 1519 vs 64 × 8: 1589 (7/6-world shards, SMT, peak RSS 29 GiB) | keep ≤ 8 |
| pin each worker (main + PhysX threads) to the two hardware threads of one core | 1510 / 1581 vs 1654 / 1648 decisions/s | rejected (PhysX threads and the main thread compete on one core) |
| disable `omni.physx.fabric` / `/physics/fabricEnabled` to drop its USD notice listener | crouch switch 423 vs 430 µs, PhysX step 1246 vs 1250 µs per tick: no effect | rejected |
| one `CollisionAPI` on each `Level_k` Xform (2 attribute writes per level change instead of 12) | trajectories differ from decision 0 (PhysX treats an Xform-level collider differently) | rejected |
| a level change costs 12 attribute writes | measured 6 (1 shape pair) / 3 (3 pairs) / 12 writes: 21 / 43 / 68 µs per change, linear in the number of writes; the PhysX listener, not Python, dominates (a dummy attribute costs 20 µs per 12 writes) | no cheaper representation preserves the six-shape compound |
| `torch.compile` for the PPO step | not possible: no C++ compiler (`g++`) on this machine and Inductor requires one even for host code | not pursued |
| channels_last, fused Adam | 2.42–2.56 vs 2.42 ms | rejected |
| scene attributes (diagnostic only, changed *before* the first play): CCD off −52 % of the PhysX step, `updateType=Asynchronous` −23 %, PGS −14 %, broadphase SAP −5 % / GPU +50 % | CCD off, async stepping and PGS change the physics (tunnelling risk, one-tick latency, different solver) | not adopted |
| disabled crouch shapes are not free | +0.125 µs per disabled shape and tick (600 extra shapes per world: +600 µs per 8-world tick); the 198 shapes per world cost ≈ 16 % of the PhysX step | not removable without lazy shape authoring (invalidates the simulation view) |
